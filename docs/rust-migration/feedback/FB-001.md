# FB-001 — transient parity mismatches under concurrent load (CLOSED, not a Rust defect)

- Symptom (2026-10-13): one slice-1 parity run executed while `node --test dist/tests/**` was running showed 19 mismatches.
- Reproduction: re-ran parity concurrently with the full TS test suite. Every mismatch had the **TS oracle** exit 1 with
  `ERR_MODULE_NOT_FOUND: Cannot find module '…/node_modules/@pilotdeck/sdk/dist/index.js'` or
  `ENOENT … packages/sdk/dist/types.js` — the Rust side was correct.
- Root cause: `tests/sdk/package-install.spec.ts` runs `pnpm --dir packages/sdk build` (six times), which cleans and
  rewrites `packages/sdk/dist`. `dist/src/cli/pilotdeck.js` statically imports `@pilotdeck/sdk` (via `sdkCli.js`), so the
  oracle cannot load while the SDK is being rebuilt. The oracle artifact was mutated mid-run.
- Fix (runner, no change to oracle/tests/comparator semantics): `oracle_broken()` detects oracle load failures; the case is
  retried up to 3 times; if still broken it is reported as **BLOCKED/oracle_unavailable and counted as a failure**, never as
  a pass. Verified: concurrent run → 62 matched, 9 cases recovered after retry, 1 BLOCKED, 0 real mismatches.
- Gate rule added: official parity evidence must be produced with no concurrent `npm test`/SDK build (idle runs: 63/63).
